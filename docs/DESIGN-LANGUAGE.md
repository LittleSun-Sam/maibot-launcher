# MaiBot Launcher 设计语言（DESIGN-LANGUAGE）

> 这份文档是**令牌层的说明书**：每一条写清「令牌 → 值 → 用途 → 为什么是这个值」。
> 代码是真源（`src/renderer/styles/tokens.css`），文档负责解释**取舍**。
> 冲突时以代码为准，并把文档改过来 —— 本项目已经吃过「注释与实现不一致」的亏
> （见 `docs/SKILL-AUDIT.md` 里"注释与实现不符的 16 处"）。
>
> 复现所有数字：
> ```pwsh
> $env:NODE_OPTIONS=""
> node scripts/legacy/theme-contrast-check.mjs    # 颜色/对比度实测表
> node patch-v1-gate/craft-40-verify.mjs          # 运行中的界面里读 34 个令牌 + elevation 证据
> ```

---

## 0. 这一层要解决的问题

用户原话：

> 整个大 UI 主题粗糙，**不是少了动画啥的，就是一个壳子，没有下料**。

把这句话翻译成可施工的判断：界面由「白底 + 白卡 + 1px 细边」三件东西组成，而这三件
**彼此之间没有层级关系**：

| 病根 | 实测证据 | 后果 |
| --- | --- | --- |
| 四档"表面"全挤在一档 | `#ffffff / #f7f9fc / #f1f5fb / #f4f7fb` 互差不到 4/255 | 卡片与页底几乎同色，卡"浮不起来" |
| 唯一的边界是一根 8% 黑线 | 白卡上对比度 **1.17:1** | 肉眼几乎看不见边界，用户只感到"糊" |
| 阴影是单层大散射 | `0 8px 24px rgba(...,.07)` | 四边均匀变暗 → "纸片感"，不是"厚度" |
| 圆角/间距/字号有刻度但不完整 | `1.375rem`、`26px`、`0.375rem` 等随手值散落 | 同一屏出现差 2px 的对齐错误 |

于是这一层的任务是**下料**：把"层级 / 边缘 / 材质 / 状态"四件事做成可复用的刻度。
**不是加动效** —— 全篇没有新增一处装饰性动画。

## 1. 中性色阶（`--neutral-*`）

### 1.1 值

一支**极轻冷偏**的中性阶（色相 220 上下，蓝分量比红分量高 3~6/255）。
编号方向在两套主题里一致：**0 = 最亮，950 = 最深**。

| 令牌 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--neutral-0` | `#ffffff` | `#ffffff` | 卡片、浮层的"最亮面" |
| `--neutral-25` | `#fcfdfe` | `#f7f9fc` | hover 时整卡提亮一档（几乎不可见） |
| `--neutral-50` | `#f8fafc` | `#eef1f6` | 次级面：输入框、次级卡 |
| `--neutral-100` | `#f1f4f9` | `#dfe4ec` | hover 底、表头 |
| `--neutral-150` | `#eaeef5` | `#c7cedb` | 凹陷面：日志列表、代码块 |
| `--neutral-200` | `#e5e9f0` | `#9aa2ac` | 可见的分隔线 |
| `--neutral-250` | `#dde2ea` | `#6f7681` | 强边线：输入框、分段槽 |
| `--neutral-300` | `#cfd5df` | `#4d545e` | 禁用边框、进度槽 |
| `--neutral-400` | `#a9b0ba` | `#3b4148` | 禁用文字 / 占位符 |
| `--neutral-500` | `#8b93a0` | `#333940` | 刻度中位（当前界面未直接用） |
| `--neutral-600` | `#6b7078` | `#2d333a` | 四级墨色：版本号、路径、日期 |
| `--neutral-700` | `#5f6570` | `#292f36` | 三级墨色：次级说明 |
| `--neutral-800` | `#3f454d` | `#23272d` | 正文 |
| `--neutral-900` | `#1a1d21` | `#1c1f24` | 标题 / 卡片底 |
| `--neutral-950` | `#14171c` | `#14171b` | 最深一档（刻度储备） |

### 1.2 为什么带冷偏

整页底是淡蓝渐变（`--app-gradient`，160deg `#f4f8ff → #e4eeff`）。纯中性灰压上去会
显得"脏"；3~6/255 的偏差足够干净，又不会被看成"蓝灰色"而与强调蓝抢戏。
超过 10/255 就会开始读作"另一个颜色"。

### 1.3 语义映射 ①：文字

| 令牌 | 用途 | 门槛 | 浅色实测 | 深色实测 |
| --- | --- | --- | --- | --- |
| `--text-1` | 标题、主信息 | ≥13:1 | `#1a1d21` 白卡 16.91 / 最差底 13.76 | `#e8eaed` 13.71 / 10.80 |
| `--text-2` | 正文 | ≥8:1 | `#3f454d` 9.68 / 7.87 | `#c2c7ce` 9.72 / 7.66 |
| `--text-3` | 次级说明 | ≥4.5:1 **全底** | `#5f6570` 5.86 / **4.77** | `#9aa2ac` 6.40 / **5.05** |
| `--text-4` | 元信息（版本号/路径/日期） | ≥4.5:1 **全底** | `#6b7078` 4.98 / **4.05** | `#98a0aa` 6.25 / **4.93** |
| `--text-disabled` | 禁用态 | ≥1.8:1 | `#a9b0ba` 2.19 | `#5c636c` 2.72 |
| `--on-accent` | **实底强调色上的文字** | ≥4.5:1 | `#ffffff` 对 `#2760e8` 5.35 | `#101216` 对 `#5b8dff` 5.98 |

**为什么 `--text-3` 要往下调**：原值 `#656b78` 在选中态淡蓝底（`#e0e8f9`）上只有
**4.35:1**，不达 AA。而这一档真实地压在"选中/淡色底"上（分段控件、页签），
所以按**最差底**取值。

**为什么 `--text-4` 不能再浅**（这一条最容易被后人"优化"坏）：它承担版本号 / 来源 /
日期 / 路径 / 空态提示，**用户要读**（审计在 8 个页面报过 133 处，光下载页 89 处）。
`#6b7078` 就是那条线：比它再浅任何一档，在 `#e0e8f9` 上都会掉到 4.0 以下。
→ 三/四级墨色的**层级差不能靠继续放浅**，只能靠字重（`--fw-medium`）与场景补。
`--text-4` 与 `--text-3` 亮度接近是**刻意的**，不是失误。

**为什么 `--text-on-accent` 只是别名**：实底按钮文字统一用 `--on-accent`，真源只有
`theme.css` 的 A/B/C 三段（浅 `#ffffff` / 深 `#101216`）。两个名字并存且不互为别名
是**会出真 bug 的二义**（深色下白字对 `#5b8dff` 只有 3.13:1）。
⚠️ 反向接线（`theme.css` 指回 `--text-on-accent`）会形成**变量环**，两个名字会
一起在计算值阶段静默失效 —— `craft-40-onaccent-fix.mjs` 里有一条专门断言禁止它。

### 1.4 语义映射 ②：边框（四档）

| 令牌 | 浅色 | 深色 | 用途 | 浅色白卡上对比度 |
| --- | --- | --- | --- | --- |
| `--line-hairline` | `rgba(0,0,0,.08)` | `rgba(255,255,255,.08)` | 只是"防止两块同色面糊在一起" | 1.17:1 |
| `--line-divider` | `rgba(0,0,0,.07)` | `rgba(255,255,255,.07)` | 反复出现的行分隔（必须比 line 轻） | 1.15:1 |
| `--line` | `rgba(0,0,0,.10)` | `rgba(255,255,255,.10)` | 常规分隔线 | 1.21:1 |
| `--line-strong` | `rgba(0,0,0,.14)` | `rgba(255,255,255,.18)` | 控件边框 / 需要明确"这是边" | 1.35:1 |
| `--line-card` | `rgb(15 23 42 / 6%)` | `rgb(255 255 255 / 8%)` | 卡片外沿（**不该被看见**） | 1.13:1 |
| `--line-inset` | `rgb(255 255 255 / 70%)` | `rgba(0,0,0,.35)` | 凹陷区上沿的内影线 | — |

**关键改动**：原来界面把 hairline 当成**唯一**的边（卡片、输入框、分隔线全用它），
于是所有边界同样弱、同样平 —— 这是"壳子感"的直接来源。四档分开后，
"做工"才有地方落：卡片的边最轻（厚度交给 elevation），控件的边最重。

深色的力度比浅色高一档（10% vs 8% 起步）：深底上的低透明度白线视觉差更小。

### 1.5 语义映射 ③：表面

| 令牌 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--surface-sunken` | `--neutral-100` | `#121417` | 比页底更深（滚动区、代码块） |
| `--surface-1` | `--neutral-0` | `--neutral-900` | **卡片 / 浮层 = 最亮面** |
| `--surface-2` | `--neutral-50` | `--neutral-800` | 次级面（输入框、次级卡） |
| `--surface-3` | `--neutral-100` | `--neutral-700` | hover 底、表头 |
| `--surface-raised` | `--neutral-0` | `--neutral-800` | 浮层里的"再浮一层"（下拉、popover） |
| `--surface-inset` | `--neutral-150` | `#101215` | 凹陷区（日志列表底） |
| `--surface-field` | `--neutral-50` | `#23272d` | 表单控件底 |

**次序不许乱**（浅色与深色都是）：凹陷 < 页底 < 卡片 < 次级 < hover。
乱掉之后会出现"输入框比卡片暗"这种说不清的感觉，**而且没有任何报错**。
深色下这条尤其重要，因为深色**不靠阴影分层，靠亮度差**（黑阴影压在深底上几乎看不见）。

## 2. 层级与阴影（`--elevation-*`）

### 2.1 三层叠加，不是一个大阴影

"卡片有做工"的物理原因只有三条，缺一条就会退回"纸片"：

1. **`--edge-top`（1px 内顶高光）**：光从上方打在材质上沿。
   浅色 `inset 0 1px 0 rgb(255 255 255 / 78%)`、深色 `rgb(255 255 255 / 7%)`。
   这是"有厚度"与"一张纸"的分水岭，成本只有 1px。
   ⚠️ 深色用**白**而不是黑：深底上的黑顶线等于没有。
2. **近距触地阴影**：1~4px 偏移 + 小模糊，勾出"它压住了下面"。
   必须近、必须小 —— 大而软的阴影读不出"接触"。
3. **远距柔和扩散**：8~32px、低透明度、**负 spread**（收紧，避免糊成一片）。

### 2.2 四档完整规格

| 令牌 | 用途 | 浅色规格 | 深色规格 |
| --- | --- | --- | --- |
| `--elevation-0` | 贴底：列表行、静态块 | `edge-top, 0 1px 1px rgb(16 24 40/4%)` | `edge-top, 0 1px 1px rgb(0 0 0/25%)` |
| `--elevation-1` | 微浮：输入框、次级卡、hover 行、选中档 | `edge-top, 0 1px 1px -.5px 6%, 0 2px 4px -1px 8%` | `edge-top, 0 1px 1px -.5px 30%, 0 2px 6px -1px 32%` |
| `--elevation-2` | 浮起：**主卡**、下拉 | `+ 0 8px 20px -6px 10%` | `+ 0 10px 24px -8px 42%` |
| `--elevation-3` | 高浮：模态、popover、toast | `edge-top, 0 1px 1px -.5px 5%, 0 4px 8px -2px 10%, 0 14px 32px -10px 14%` | `edge-top, …, 0 16px 36px -10px 48%` |
| `--elevation-modal` | 比 3 再远一档（要压住整页） | `+ 0 18px 44px -12px 22%` | `+ 0 20px 48px -12px 60%` |

旧名 `--shadow-1 / --shadow-2 / --shadow-card` 保留并指向新档（页面在引用）。

### 2.3 ⚠️ 与焦点环的相互作用（T2/T3 必读）

`theme.css` 里有一条按用户要求**保留**的规则：

```css
:focus-visible { box-shadow: var(--focus-ring) !important; }
```

理由见那边的注释：选中态类自己写的 `box-shadow`（0,2,0）会把全局焦点环（0,1,0）
整条盖掉，越是选中的控件越看不见焦点在哪 —— 可达性是底线。

**副作用**：元素一旦进入键盘焦点，它的 elevation 会被**整条替换**成焦点环。
所以卡片/面板的 elevation 要挂在外层容器或伪元素上，别指望"有焦点环还留着 elevation"。

配套规则（T2 已落地，写在这里免得被改掉）：**组件自己的 `:focus-visible { box-shadow: var(--focus-ring) }`
（scoped 特异性更高）会赢过全局那条，两者视觉一致，因此不存在"同一个控件两种焦点环"**。

## 3. 圆角阶梯（`--r-*`）

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--r-2xs` | 4px | 徽标、复选框外框、2~4px 高的小片 |
| `--r-xs` | 6px | 菜单项、内嵌小面（`--r-menu` 同值，旧名保留） |
| `--r-sm` | 8px | 同心补偿档（外 12 内 8；仅此用途） |
| `--r-ctl` | 10px | **所有可点控件**：按钮、输入框、下拉、分段档（`--r-input`/`--radius-sm` 同值） |
| `--r-card` | 14px | 卡片与弹窗（`--r-modal`/`--radius-lg` 同值） |
| `--r-panel` | 16px | 大面板 / 整页级容器（比卡再大一档，读起来更"厚"） |
| `--r-pill-ctl` | 12px | 分段槽、滚动条拇指的"半圆" |
| `--r-pill` | 999px | 真胶囊/圆形（状态点、开关轨、滚动条拇指） |

两条规则：

1. **同级用同一档** —— 同一屏里两个按钮圆角不同，观感立刻毛糙（历史问题：
   `SegmentedControl` 外槽 10px、内层 6px 本来是对的，但有人写过 8px）。
2. **嵌套时内层必须比外层小** —— 外 12 内 8、外 14 内 10、外 16 内 12。
   内层等于外层时折角会"咬"出一个小尖。

⚠️ 现有值一个都没改（统一改圆角 = 全站回归），只补 `--r-2xs:4` 与 `--r-panel:16`。

## 4. 间距阶梯（`--sp-*`）

| 像素 | 令牌 | 用途 |
| --- | --- | --- |
| 2 | `--sp-2xs` | 微调（分段槽内距） |
| 4 | `--sp-1` | 图标内边距、行内微间距 |
| 6 | `--sp-1h` | **图标与文字之间** |
| 8 | `--sp-2` | 行内控件之间 |
| 10 | `--sp-2h` | 行内控件之间的宽松档 |
| 12 | `--sp-3` | 行间距、卡片内分段 |
| 16 | `--sp-4` | 区块内边距 |
| 20 | `--sp-4h` | 按钮横向内边距的宽松档 |
| 24 | `--sp-5` | **卡片内边距** |
| 28 | `--sp-5h` | 区块之间 |
| 32 | `--sp-6` | 页面区块之间、空态内边距 |

**为什么命名是 `--sp-N` 而不是像素即名字**：这是项目既有约定（`--sp-5` 就是 24px），
改成"像素即名字"会导致全站页面都要改。所以**现有 `--sp-1..--sp-6` 的字面值一个都没动**
（4/8/12/16/24/32 被大量引用），只补 6 与 20 两档，并保留 `--sp-1h` / `--sp-4h` 这种
"插值档"命名，避免 `--sp-5` 在别人眼里"到底是 20 还是 24"。

替代的魔数：`0.375rem`(6) / `0.125rem`(2) / `0.25rem`(4) / `1.375rem`(22→24) / `2.125rem`(34→32)。

⚠️ **间距刻度只表达"距离"，不表达"控件高度"**：控件高度走 `--h-ctl`(32) / `--h-ctl-sm`(28)。
`FieldRow` 的 `min-height` 就是 32px 而不是 `--h-ctl-sm` —— 它右列放的是 32px 高的控件，
行高若取 28px，整组字段的纵向节奏会比控件本身紧 4px（实测观感是"挤"）。

## 5. 字号 / 行高 / 字距 / 字重 + 四类语义排版

### 5.1 阶梯

| 档 | 字号 | 行高 | 字距 | 用途 |
| --- | --- | --- | --- | --- |
| `2xs` | 10px | 14px | `+0.01em` | 徽标内数字、极小标注 |
| `xs` | 11px | 14px | `+0.008em` | 计数、角标 |
| `sm` | 12px | 16px | `+0.005em` | **附注**、标签、控件文字 |
| `body`/`md` | 13px | 20px | `0` | **正文**（全站底座） |
| `title` | 15px | 22px | `-0.005em` | **区块标题** |
| `lg` | 17px | 24px | `-0.01em` | **页面标题** |
| `xl` | 19px | 24px | `-0.015em` | 大标题（品牌） |
| `2xl` | 20px | 28px | `-0.015em` | 最大一档（补缺） |

**字距规则**：小字**正**、正文 `0`、大字**负**（SKILL §15）。
⚠️ **中文**与西文不同：西文大字收紧到 `-0.02em` 很舒服，中文方块字在 `-0.02em`
下开始互相压边。所以这套只收到 `-0.005 / -0.01 / -0.015`，且正文与附注一律 `0` 或极小正值。
`craft-20-verify` 有断言守着这三个符号方向，别动。

**字重上限 600**：中文在 700 会糊。`400 / 500 / 600` 三档
（`--fw-regular` / `--fw-medium` / `--fw-semibold`；`--fw-normal`、`--fw-bold` 是旧名接线）。

### 5.2 四类语义排版（成对给，避免"改了字号忘行高"）

| 角色 | 字号 | 行高 | 字距 | 字重 | 令牌前缀 |
| --- | --- | --- | --- | --- | --- |
| 页面标题 | 17 | 24 | `-0.01em` | 600 | `--type-page-title-{fs,lh,ls,fw}` |
| 区块标题 | 15 | 22 | `-0.005em` | 600 | `--type-section-title-{fs,lh,ls,fw}` |
| 正文 | 13 | 20 | `0` | 400 | `--type-body-{fs,lh,ls,fw}` |
| 附注 | 12 | 16 | `+0.005em` | 400 | `--type-caption-{fs,lh,ls,fw}` |

另有 `--type-read-lh: 22px`：长段落（说明、EULA）用 20px 行高偏紧。

### 5.3 两个**不属排版阶梯**的字面字号（刻意保留，别"清理"掉）

| 位置 | 值 | 为什么不用令牌 |
| --- | --- | --- |
| `EmptyState.vue` 的 `.empty-ico` | `26px` | 它是**图标字形尺寸**，不是文字排版。图标大小跟随的是图标本身的观感，跟正文阶梯没有任何关系；映射到 `--fs-*` 会让"改正文阶梯"意外改掉空态图标的体积。 |
| `DownloadProgress.vue` 的 `.dl-tag`（版本标签里的字形） | `12px` | 同上：字形尺寸。 |

判据（控件层统一按这条判）：**字号位走 `--fs-*`，间距位走 `--sp-*`，圆角位走 `--r-*`；
元件尺寸（`.dot` 8px、滑块 18px、开关轨 24px、进度槽 6px、spinner 环 18/30/13px）与
图标字形尺寸保留字面值。** 间距刻度管"距离"，不管"元件有多大" —— 混用会让刻度失去
可维护性（将来调间距时会连带改到元件，反之亦然）。

## 6. 状态层（`--state-*`）

**全部 alpha 叠加，不新增实色。** 三个理由：

- 实色 hover 只对某一种底成立（白卡上好看，压在淡蓝底上就变脏）；
- alpha 叠加在**任何**底上都成立（合成结果自动跟底色走）；
- 不破坏文字对比度 —— 底变了，墨色关系仍然成立。

| 令牌 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--state-hover` | `rgb(15 23 42 / 4.5%)` | `rgb(255 255 255 / 5.5%)` | 悬停整块反馈 |
| `--state-pressed` | `rgb(15 23 42 / 8%)` | `rgb(255 255 255 / 9%)` | 按下瞬间（比 hover 重，且要立刻可见） |
| `--state-selected` | `rgb(15 23 42 / 6%)` | `rgb(255 255 255 / 7%)` | 持久选中 |
| `--state-selected-strong` | `rgb(15 23 42 / 11%)` | `rgb(255 255 255 / 12%)` | 选中态更强一档（开关轨道） |
| `--state-hover-strong` | `rgb(15 23 42 / 7%)` | `rgb(255 255 255 / 9%)` | 带底元素上的 hover |
| `--state-disabled` | `rgb(15 23 42 / 4%)` | `rgb(255 255 255 / 5%)` | 禁用 |
| `--state-scrim` | `rgb(15 23 42 / 32%)` | `rgb(0 0 0 / 55%)` | 模态遮罩 |

**深色力度更高**（5.5% vs 4.5% 起步）：人眼对暗部亮度差不敏感，同样的透明度在深底上
的视觉差更小。

**常见漏做项**：选中项自己的 hover 需要**再叠一层**（`--state-hover-strong`），
否则在已经带底的选中态上看不出变化。

旧名 `--fill-hover / --fill-active / --fill-selected / --fill-disabled` 指向同一批值。

## 7. 材质（`--material-*` / `--chrome-*`）

标题栏是**唯一**一层材质（SKILL §12 明确禁止把浅色半透明叠在另一层浅色半透明上，
可读性会塌 —— 以后要加第二处材质，先读那一条）。

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--material-opacity` | `0.76` | 材质浓度。低于 0.7 文字与滚动内容互相干扰；高于 0.85 退化成实心条 |
| `--material-blur` | `20px` | 模糊半径 |
| `--material-saturate` | `180%` | 饱和度补偿（模糊会掉色） |
| `--titlebar-material` | `color-mix(in srgb, var(--surface-0) 76%, transparent)` | 标题栏底 |
| `--titlebar-edge` | 浅 `rgb(255 255 255/55%)` / 深 `8%` | 顶光（光打在材质上） |
| `--chrome-scroll-dim` | 浅 `linear-gradient(rgb(16 24 40/8%) → 0%)` / 深 `rgb(0 0 0/42%)` | **内容滚过时的暗化带** |
| `--chrome-scroll-h` | `12px` | 暗化带高度（原写死 10px） |
| `--chrome-line` | 浅 `0 1px 0 rgb(16 24 40/6%)` / 深 `30%` | 下沿 1px 染色（**只在滚动时出现**） |
| `--chrome-shadow` | 浅 `0 1px 2px rgb(16 24 40/4%)` / 深 `25%` | 整体轻阴影 |
| `--overlay-material` | `color-mix(… var(--surface-raised) 92%)` | 下拉/popover 的材质（比 chrome 更"实"） |
| `--overlay-blur` | `blur(12px) saturate(140%)` | 同上 |

**为什么暗化带是"有方向的"**：SKILL §12 要求用**滚动边效果**而不是一根硬分隔线。
上下渐变的遮罩读起来像"内容钻到 chrome 下面去了"，一根 1px 线读起来像"这里画了条线"。
它由 `.shell.is-scrolled` 驱动 —— 静止时内容并不与 chrome 重叠，那时不该有线。

**降级**（`@media (prefers-reduced-transparency: reduce)`）：不能只把 blur 关掉 ——
半透明层被强制不透明时底下内容透不出来，**必须同时把底色补成实色**。
所以这里改的是**令牌本身**（`--material-opacity: 1`、`--titlebar-material` → 实色），
所有用同一批令牌的地方一起降级。暗化带**保留**（它不依赖透明度）。

`@media (prefers-contrast: more)`：边线加重到"明确可见"，材质全部走实色，
内顶高光归零（高对比下不要装饰性明暗）。

## 8. 焦点环（`--focus-ring`）

```css
:focus-visible { outline: none; box-shadow: var(--focus-ring) !important; }
```

- 值：浅 `0 0 0 2px rgba(39,96,232,.35)`、深 `0 0 0 2px rgba(91,141,255,.45)`。
- **`!important` 必须保留**：全局规则是最低优先级（0,1,0），而"选中/主操作"变体
  （`.menubar-item.active`、`.pill.v-solid`、`.swatch.on`）自己写了 `box-shadow`（0,2,0），
  会把焦点环整条盖掉 —— 实测表现是"越是选中的控件越看不见焦点在哪"。
- 那条规则里**不能**写 `border-radius`：加上它会在获得焦点的一瞬间把元素形状改掉
  （开关是 999px 胶囊，一按 Tab 就变方角）。
- 组件自己的 `:focus-visible` 统一用同一个 `var(--focus-ring)`，不要就地写
  `2.5px` 的 `--accent-tint`（10% 透明度，键盘用户几乎看不见）。

## 9. 主题色（未改动）

`--accent`（浅 `#2760e8` / 深 `#5b8dff`）与 `--accent-ink`（浅 `#255cde` / 深 `#6997ff`）
**保持原值**，理由用实测数据说话：

| 检查 | 浅色 | 深色 |
| --- | --- | --- |
| `--accent` 当正文色压白卡 | 5.35:1 | 5.27:1 |
| `--accent` 压选中态淡色底 | **4.35:1（不达 AA）** | **4.15:1（不达 AA）** |
| `--accent-ink` 压选中态淡色底 | 4.66:1 | 4.63:1 |
| 白字压 `--accent` 实底 | 5.35:1 | 3.13:1（改用墨字 5.98:1） |

→ 结论：品牌色本身达标，**不达标的是"当小字压在淡色底上"这个用法**，
所以用 `--accent-ink` 专门承担那一档。改 `--accent` 反而会牵动整站品牌色。

## 11. 控件契约（T2 落地结果）

基础控件（`src/renderer/components/ui/**`）的材质用法，改这些请先读本表：

| 控件 | 底 | 边 | 层级 | 状态 |
| --- | --- | --- | --- | --- |
| `PanelCard`（`.card`） | `--card-bg` | `--line-card`（1px，最轻） | `--elevation-2` | 头/身之间一条 `--line-divider` 分段 |
| `PillButton` | 实底 `--theme-color` + 8% 受光渐变；ghost `--surface-1` | ghost `--line-strong` | 实底 `--elevation-1`；ghost `--edge-top-subtle` | hover 用叠加层（**不用 `filter: brightness`**，它会把白字一起洗掉）；按下由全局 `scale(.97)` 表达 |
| `TextInput`（`.tinput`） | `--surface-2` | `--line-divider` | `--edge-inset`（凹） | hover 边加深；focus `--focus-ring` + 内影；disabled `--state-disabled` |
| `SegmentedControl`（`.seg`） | 槽 `--seg-bg` | 槽 `--line-divider` | 槽 `--edge-inset`；选中档 `--edge-top` + `0 1px 2px` | 选中档内层圆角 `--r-xs`（外 10 − 内距 2 同心） |
| `ToggleSwitch` | 轨 `--state-selected-strong` | — | 轨 `inset 0 1px 2px`；滑块 `inset` 高光 + 双层触地 | hover 只动轨道底色/滑块阴影（**不用 `filter: brightness`** —— 会连白色滑块一起压暗，那正是"脏"的来源）；聚焦环 `--focus-ring` |
| `ToastStack`（`.toast`） | `--toast-bg`（**两套主题都是深底**） | — | `--elevation-3` | 计数徽标 `--sp-1h` |
| `VersionPicker`（`.vp-pop`） | `--overlay-material` | `--line-hairline` | `--elevation-3` | 列表项 hover `--state-hover` |

**共用规矩**：

- 实底按钮文字**统一** `--on-accent`（不要写 `#fff`，也不要写 `--paper-full`）。
- 浮层（popover/modal/toast）文字与底的对比度必须单独验：它们在"变化中的底"上。
- 装饰性动效一律不加；按下反馈走全局 `:active { transform: scale(.97) }`（SKILL §1：
  反馈发生在按下瞬间，且只动合成器属性）。

### 11.1 已知上限：中间调强调色下"选中档文字"的对比度

`SegmentedControl` 的选中档文字走 `--accent-ink` —— 这是 settings-rebuild 实测后
从 `--accent` 换过来的：用户自选珊瑚红这类**中间调**强调色时，`--accent` 当小字压在
淡色选中底上只有 **4.05:1**（不达 AA）；`--accent-ink` 是专为"当小字用"准备的那一档，
同一底色下 4.66:1。

**但它不是万能的。** 强调色是用户可选的（8 个预设 + 边界值），`--accent-ink` 由主题色
派生，所以"中间调强调色 + 最浅选中底"这个组合的下限就压在 4.5 附近：

- 8 个预设色 + 常规深浅两套主题：全部 ≥4.5（实测最低 4.63）；
- 用户手工取一个**亮度正好卡在中间**的强调色（例如高饱和珊瑚红）压在最浅选中底上：
  可能落在 **4.4~4.5**，属于"擦线"，不是崩坏。

**做不到全色域 ≥4.5 是刻意的取舍。** 另一条路是把选中底压深，但那会让整条分段控件
在浅色主题里变重，与"轻"的整体调性冲突。将来若要收紧，正确做法是**给强调色加亮度
约束**（选色时拒掉 L 落在 0.55~0.75 区间的值），而不是继续加深底色。
settings-rebuild 在设置页给用户看实测徽标的做法值得沿用到所有"用户可选色 × 文字"
的地方 —— 那比在 CSS 里硬调更诚实。
