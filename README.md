# MaiBot Launcher

基于 **Electron + Vue 3** 的桌面启动器，用来在本机管理 **MaiBot** 与 **SnowLuma** 这两个服务。

---

## 这是什么

MaiBot（Python 后端）和 SnowLuma（协议端 / WebUI）要跑起来，需要装环境、装依赖、按顺序启动、
盯着端口、翻日志排错、升级前留一份备份。

这个启动器把这些事从命令行搬到图形界面：装、启停、看日志、升级、备份还原，
都在同一个窗口里完成。它只负责**托管进程**，不是 MaiBot 或 SnowLuma 的一部分。

---

## 功能

- 服务启停：MaiBot 与 SnowLuma 的启动 / 停止 / 单独重启，界面实时显示运行状态。
- 全部启动与全部停止：按顺序启动（SnowLuma 先、MaiBot 后），停止时反序。
- 看门狗：服务异常退出后自动重启，次数上限可设（设为 0 即关闭）。
- 端口与接线自检：真实连接 SnowLuma 的 WebUI 端口与 OneBot 端口，并读取 MaiBot 目录下的适配器插件。
- 首跑部署引导：从环境体检一路引导到服务跑起来（见下文）。
- 日志聚合：两个服务的输出按时间合并成一条流，每行标注来源，ANSI 颜色会真正渲染出来。
- 日志操作：按来源筛选（全部 / MaiBot / SnowLuma）、复制、导出为 `.log` 文件、清空缓冲。
- 交互式终端：直接向服务进程发送标准输入，用来过 MaiBot 首次启动的协议确认。
- 备份与还原：升级前自动备份旧版本，之后可以在设置里把某个备份还原成当前使用的安装。
- 安装与升级：从上游 Release 选版本安装、升级；升级时保留 `config`、`data`、`logs`、
  `models`、`.env`、`bot_config.toml`。
- 应用内检查更新：启动器自身的版本检查、下载与安装（见下文）。
- 托盘常驻：关窗后从托盘启停服务、打开主界面、打开日志目录、重启启动器。
- 系统占用与数据占用：CPU 与内存实时采样、磁盘可用空间，以及各数据分类的体积统计与清理。
- 界面：深色 / 浅色 / 跟随系统，主题色可换、可自定义。

## 系统要求

- Windows 10 / 11（x64）。
- 启动器本身不需要 Python。**要在本机跑 MaiBot 则需要 Python 3.12 或更新**，并且需要 Git；
  uv 是官方推荐但非必需（缺了就用 pip 装依赖）。这些由启动器的环境体检真实探测，缺什么会写明。
- 磁盘：每安装一个服务建议预留约 800 MB 可用空间（含解压余量）；MaiBot 的模型文件另算。
- 内存：启动器自身占用不大；MaiBot 与 SnowLuma 是独立进程，按它们自己的要求准备。

## 安装

1. 打开 [Releases](https://github.com/LittleSun-Sam/maibot-launcher/releases/latest)，
   下载 `MaiBot Launcher Setup x.y.z.exe`。
2. 双击安装。安装包是 NSIS 一键式，装到当前用户，**不需要管理员权限**，
   会创建桌面与开始菜单快捷方式。
3. 首次启动会进入部署引导。

---

## 第一次使用

部署引导分六步，每一步都是"先真的检测、再给结论"，检测不通过不会自动打勾：

1. **环境体检** —— 读 Python / Git / uv 的真实版本与目标磁盘可用空间，缺哪一项就直说。
2. **选安装位置** —— 选 MaiBot 的安装目录，也可以扫描本机已有的安装。
3. **安装麦麦** —— 按版本下载安装；这一步由你点击，引导只负责跳转。
4. **依赖 / 环境准备** —— 检查缺失的依赖并安装（可以先快速检查，再用完整检查读版本号）。
5. **启动服务，拿到入口** —— 启动 MaiBot，需要时也启动 SnowLuma；给出 WebUI 入口与启动日志。
6. **出口与后续** —— 汇总部署结果，并指向「新手引导」继续做接线。

装好之后的接线（在 SnowLuma 上建 OneBot 正向 WebSocket、MaiBot 侧装官方适配器插件、
配模型、让麦麦回第一句话）在软件内的「新手引导」里逐步说明。

### 管理器不会替你做

- **不修改 MaiBot 与 SnowLuma 的源码**，也不重新实现它们的启动逻辑，
  只以独立进程方式调用（命令行调用 + 标准输出捕获）。
- **不接管它们的配置**。需要改配置时优先走它们自己提供的 WebUI ——
  例如 SnowLuma 的 OneBot 正向 WebSocket 服务器要在它自己的 WebUI 里创建，端口也由你填，
  启动器只把建议端口显示出来，并去核对两边是否一致。
- **不代为同意上游的用户协议**。MaiBot 首次启动要在终端里输入「同意」并回车，这一步得你自己做。
  协议端只有 SnowLuma 一种，它不需要本机安装 QQ 客户端。
- **不打包上游项目**。设置页里的「下载安装」只是替你向官方 GitHub Releases 发起一次下载，
  落盘的是官方原包，后续安装仍由你完成。

## 日常使用

- **启停**：总览页对每个服务有启动 / 停止 / 重启；托盘菜单里也有同样一组动作。
- **看日志**：日志页是单一数据流，双击顶部「日志」标签可切换只看某个服务；
  右上角可以复制、导出、清空。启动器自己的运行日志不在这一页，见下文的数据目录。
- **升级前后**：升级会先备份旧版本，再原子替换，失败自动回滚。
  之后可以在设置里看到受管目录下的版本列表，选中一个备份点「还原」即可换回来。
- **检查更新**：设置 → 关于 → 检查更新（关于页的版本号旁边也有同一个入口）。

## 数据放在哪

启动器的数据都在 `%APPDATA%\maibot-launcher`（即 Electron 的 `app.getPath('userData')`）：

| 路径 | 内容 |
|---|---|
| `backend-settings.json` | 设置文件（端口、目录、主题、通用选项等） |
| `logs\launcher.log` | 启动器自身的运行日志（含渲染层的未捕获异常） |
| `maibot-data\models` | 模型文件 |
| `maibot-data\records` | 聊天记录 |
| `maibot-data\cache` | 缓存 |
| `maibot-data\exports` | 从工具箱导出的配置文件等 |

清理数据按分类进行：日志按修改时间保留最近 7 天，其余分类为整体删除。
删除前有预演，预演与实际删除共用同一份计划，说删什么就删什么。

MaiBot 与 SnowLuma 自己的数据（配置、聊天记录、日志）在**它们各自的安装目录**里，
启动器不搬动、不改写。

### 备份的命名规则

升级与安装替换时，旧目录被整体保留在同级位置，命名是：

- `<目录名>.backup-<时间戳>` —— 升级产生，失败时用来回滚；
- `<目录名>.old-<时间戳>` —— 安装 / 还原过程中的替换产生。

时间戳是 ISO 时间去掉了冒号与点，例如 `2026-09-28T18-00-05`。
备份**不会被自动删除**，你可以在设置里查看并清理；删除前会校验目录名是否符合上述规则。

## 更新是怎么做的

1. **检查**：读取启动器仓库的 Release 元数据与当前版本比较；未配置更新源时会如实说明，不会假装已是最新。
2. **看更新内容**：点击后打开二级窗口，显示当前版本、最新版本与该版本的更新说明
   （已是最新时，显示的就是当前这一版的说明）。
3. **下载**：按通道顺序依次尝试（加速通道 → 备用通道 → 直连 GitHub），每个通道内默认
   **多线程分段下载**，通道不支持分段时退回单连接；某个通道失败会把真实原因记下来再换下一个。
4. **校验**：先核对字节数是否与 Release 元数据一致；元数据里有 SHA-256 就一并比对。
   校验不过的包会被删掉并换通道，绝不当成功；安装前会再核对一次磁盘上的文件。
5. **安装**：校验通过后才运行安装包。

失败时会如实报出原因（哪条通道、什么错误、字节数或摘要对不上），不会显示成成功。

## 卸载

从 Windows 的「设置 → 应用 → 已安装的应用」里找到 MaiBot Launcher 卸载即可。

卸载程序**不会删除数据目录** `%APPDATA%\maibot-launcher`（配置、日志、缓存在卸载后仍然保留）。
想彻底清干净就卸载后手动删除该目录；MaiBot 与 SnowLuma 的安装目录也需要你自己处理。
